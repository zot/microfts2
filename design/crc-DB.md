# DB
**Requirements:** R1, R2, R17, R20, R22-27, R29, R32, R33, R35, R37-42, R51-53, R55, R56, R63-69, R77-82, R84-88, R91-94, R96-99, R101, R103-107, R110-112, R115-122, R124, R125, R127-130, R132, R134-137, R139-144, R146, R147, R150-153, R156-168, R176, R178-191, R196-200, R202, R203, R206, R213-244, R246-296, R298, R336-341, R343, R345, R346, R348, R358, R360, R361, R363-370, R374-378, R418-425, R427-432, R439, R442-464, R469-498, R500, R513-516, R520, R524-530, R546-562, R571, R592, R594-600, R604-606, R608, R609, R623-625, R655-657, R660-703, R705-707, R709, R710, R712, R715, R716, R719, R720, R726-739, R742, R743, R745-798

Main database handle. Owns a `*bbolt.DB` with a single named bucket. All records (I, H, C, F, N, T, W) are prefix-distinguished within that one bucket. Chunks are deduplicated by content hash. Provides the public library API.

## Knows
- db: *bbolt.DB handle — owned; shared with the host process via DB() (R661)
- bucketName: bbolt bucket name (single, default "fts") — the bucket is obtained from the txn per operation (R662, R667)
- settings: loaded from I records (chunking strategies, caseInsensitive, aliases, caseInsensitiveFilenames — R736)
- filename key: `FilenameKey(path)` folds the path with `strings.ToUpper` when settings.CaseInsensitiveFilenames is set, returns it unchanged otherwise, and never folds `tmp://` paths (R737, R738, R743). Every N key comes from it through the unexported `encodeFilename`/`finalKey` wrappers (R739); the stored spelling (F Name, final N value) is never folded (R763)
- respelling: storePrepared first runs respell — on a folded final-key hit whose stored name differs from the given path, rewrite the final N value and F Name, commit, then refresh pathCache, drop the frecordCache entry, and return ErrAlreadyIndexed (R764, R746). An identical spelling falls through to addFileInTxn's guard and writes nothing (R747); with the option off the keys differ, so nothing is respelled (R748). Reindex respells by re-adding (R745)
- trigrams: Trigrams instance configured from settings (case insensitivity, byte aliases)
- chunkers: map[string]any — in-memory chunker strategies (each satisfies Chunker, FileChunker, or both)
- Record structs: CRecord (with ContentLen), FRecord, TRecord, WRecord — MarshalValue / UnmarshalXValue encode/decode (R735); H record is a bare chunkid varint, no struct
- TxnHolder: interface `Bucket() *bbolt.Bucket` — CRecord implements it (plus a `Tx()` convenience); unexported bucketWrap wraps raw buckets from View/Update blocks (R734)
- Supporting types: TrigramEntry, TokenEntry, FileChunkEntry
- TrigramCount: exported struct {Trigram uint32, Count int}
- TrigramFilter: exported function type deciding which query trigrams to search with
- ChunkFilter: exported function type `func(chunk CRecord) bool` — predicate on full chunk data
- stock filters: FilterAll, FilterByRatio, FilterBestN. FilterByRatio takes `(maxRatio float64, minCount int)` and skips a trigram only when it is both non-discriminating and expensive to scan — over `maxRatio` of chunks AND at least `minCount` postings (R141, R675). It only discriminates at `totalChunks >= 2`; below that it returns all trigrams unmodified, independently of `minCount` (R674)
- stock score functions: ScoreOverlap (pure), ScoreBM25 (closure factory)
- MultiSearchResult: exported struct {Strategy string, Results []SearchResult}
- ChunkResult: exported struct {Path, Range, Content string, Index int, Attrs []Pair, Missing bool} (R703)
- overlay: *Overlay — in-memory tmp:// document store (lazily created)
- RecordStats: exported struct {Count, KeyBytes, ValueBytes int64} — per-prefix aggregate
- pathCache: map[uint64]string — cached fileid→path mapping, lazily loaded, incrementally maintained
- pathToID: map[string]uint64 — reverse cache keyed by filename key (R742), built alongside pathCache
- frecordCache: map[uint64]FRecord — opt-in per-batch FRecord cache, nil when inactive
- ChunkCallback: exported type `func(chunkText string)` — observation callback for indexing
- IndexOption: exported type `func(*indexConfig)` — functional option for indexing methods
- indexConfig: unexported struct holding ChunkCallback
- RemoveCallback: exported type `func(tx *bbolt.Tx, orphanedChunkIDs []uint64) error` — transactional cleanup callback for file removal (R665)
- ReindexCallback: exported type `func(tx *bbolt.Tx, orphanedChunkIDs, newChunkIDs []uint64) error` — transactional cleanup callback for reindex (R665)
- PreparedFile: opaque exported type — a computed file's chunks plus its mod time, content hash, and byte length; produced by PrepareFile/PrepareContent, consumed once by StorePrepared/ReindexPrepared (R676, R679)
- PreparedAppend: opaque exported type — a computed append's new chunks plus replacedLast and the assumed last locator; produced by PrepareAppend, consumed once by AppendPrepared (R685, R686)
- ErrChunkerVersionStale: sentinel error — the append store refuses to extend a file whose recorded chunker version differs from its strategy's current one; the caller reindexes (R727)
- ErrAppendTailMoved: sentinel error — AppendPrepared refuses a prepared append whose assumed tail no longer matches the committed F record (R688)
- SplitChunk: exported struct {Chunk Chunk, Hash [32]byte} — one split chunk plus its content hash (Hash = SHA-256 over Chunk.Content); produced by SplitFile/SplitContent/SplitAppend (R690, R693)
- FileMeta: exported struct {ModTime int64, ContentHash [32]byte, FileLength int64} — file-level metadata computed by a split, consumed by AssembleFile (R690)
- PreparedChunk: opaque exported type — one chunk's content-pure grams (trigram counts + tokens); carries no hash and no position/chunker data; produced by PrepareChunk, cacheable/reusable by content hash (R694)
- PreparedEntry: exported struct {Chunk Chunk, Hash [32]byte, Grams *PreparedChunk} — a split chunk paired with its computed grams; the ordered input to AssembleFile/AssembleAppend (R695)

## Does
- Create(path, opts): create new database via bbolt.Open (lock wait bounded by opts.Timeout, R672), validate aliases (ASCII-only), create the fts bucket (CreateBucketIfNotExists), write I records with settings using data-in-key pattern. Write format version "7" I record (formatVersion constant, R797). opts no longer carry MaxDBs/MapSize (R666)
- Open(path, opts): open existing database via bbolt.Open (lock wait bounded by opts.Timeout, R672), refuse unless the version I record equals formatVersion, "7" (close the handle; the error is a `*FormatVersionError` with the stored and expected versions as fields, and names the stored version — R798, R751), load settings from I records. opts no longer carry MaxDBs/MapSize (R666)
- Close(): close the bbolt database
- DB(): return the underlying *bbolt.DB for sharing in-process (R661). The host opens microfts2 first and passes this handle to other libraries (ark), which open their own bucket in the same file; a bbolt.Tx spans all buckets (R662)
- internal helpers obtain the fts bucket from the txn (tx.Bucket) and operate on it; the former (TxnHolder, lmdb.DBI) pair collapses to a single *bbolt.Bucket (R667)
- bucket(tx): every internal helper obtains the fts bucket through it; in a writable txn it sets the handle's FillPercent to keyFill (0.9) before returning it, so a page split by right-edge appends stays 90% full (R796). bbolt caches the child handle per writable txn and applies FillPercent at commit, so one set covers the txn
- AppendKeyID(b, v) / KeyID(b): SQLite4's order-preserving varint, the encoding of every id in a key, so byte order is numeric order and new ids append at the tree's right edge (R791-R793). KeyID is bounds-checked: n == 0 on short input, n < 0 on a non-minimal encoding. makeCKey, makeFKey and makeDKey use it, and every reader of a C, F or D key decodes with it (R794); ids inside values stay LEB128 (R795)
- Version(): read "version" I record in a View txn, return (string, error)
- AddFile(path, strategy, idxOpts): check for existing N records via finalKey(path), the folded final key — return ErrAlreadyIndexed if present. Allocate fileid, create N/F records. Call Chunker.Chunks (yields Range+Content+Attrs per chunk). For each chunk: fire ChunkCallback with the chunk content if present (R473); compute the dedup hash (SHA-256 over Content, R656) and index trigrams/tokens from that same content (full-text — nothing stripped); check H record for dedup — if hit, add fileid to existing C record; if new, allocate chunkid, create H/C records (with the chunk's native Attrs, distinctTokens and tokenTotal) and queue a posting with its count for each of its trigrams (R783). Identical content dedups to one chunkid; differing content gets distinct chunkids (R657). Batch T updates across all chunks (R784). Update F record with its chunk entries. Returns (fileid, error)
- AddFileWithContent(path, strategy, idxOpts): like AddFile but also returns the raw file content. Returns (fileid, []byte, error)
- ErrAlreadyIndexed: sentinel error — caller checks with errors.Is and uses Reindex or AppendChunks instead
- RemoveFile(path): read F record to get chunk list, for each chunkid: read C record, remove fileid — if no fileids remain, the chunk is orphaned: delete C/H records, subtract its tokenTotal from totalTokens, write its D record, edit no posting (R774). Delete F and N records
- RemoveFileWithCallback(path, fn RemoveCallback): same as RemoveFile but collects orphaned chunkids during removal, then calls fn(txn, orphanedChunkIDs) inside the write transaction before commit. If fn returns error, entire txn aborts. If fn is nil, identical to RemoveFile. Empty orphan list still calls fn
- RemoveFiles(paths, fn RemoveFilesCallback): remove a batch in one write transaction. Per path, lookupFileByPath (a path not indexed is skipped), dropFileChunkOccurrences, deleteFileMeta; orphans join the dead set and no T record is rewritten (R788). Then fn(tx, removedFileIDs, orphans) once: a chunk shared only by files in the batch is orphaned when the last of them drops it. After commit, pathCache/pathToID forget every removed path. The caller bounds the batch. R754-R758
- searchConfig: embeds *DB, built by search entry points. The entire search pipeline (candidate collection, overlay merge, scoring, post-filtering, reranking) runs as methods on *searchConfig. Fields: scoreFunc, onlyIDs, exceptIDs, verify, trigramFilter, regexFilters, exceptRegexFilters, chunkFilters, proximityTopN, loose, noTmp, chunkCache
- SearchResult: Path, Range, Score (exported); chunkID, chunk (unexported). chunkID set by scoreAndResolve; chunk lazily populated by Retrieve
- WithChunkCache(cc *ChunkCache): SearchOption that stores a *ChunkCache on searchConfig — Retrieve checks it before rechunking from disk (cross-search file-read reuse)
- Retrieve(r *SearchResult): method on *searchConfig — returns chunk content. Check order: r.chunk (instant) → chunkCache.ChunkText(path, range) if present → rechunk from disk. Stores on r.chunk. Post-filters use Retrieve instead of filterResults+rechunkForVerify
- Search(query, opts): build searchConfig, extract trigrams, select via TrigramFilter (default FilterAll) using each T record's live postings for DF (R775, R786). Decode each selected trigram's T record once per query (dead postings skipped), intersect the live chunkids per term and across terms. Read C records for surviving candidates (attrs, fileids, distinctTokens) — apply ChunkFilter if present, then score using ScoreFunc with chunkCounts for the selected trigrams taken from the decoded postings (R776). Post-filters (verify, regex, proximity) use Retrieve for chunk text; verify runs only for exact search, skipped with WithLoose (R710). Return SearchResults
- SearchTerms(terms, opts): Search for terms the caller already split, each as-is (a space is part of a term, a quote a character); empty terms dropped. Search(query) is SearchTerms over parseQueryTerms's split, and verify and proximity rerank take those terms rather than re-splitting (R752, R753). SearchMultiTerms is the same for SearchMulti.
- SearchFuzzy(query, k, opts): two-phase typo-tolerant search. Phase 1: extract trigrams, tally chunkID appearances across T record posting lists and (separately) the overlay trigram maps; drop every tally entry the file restriction rejects (fileRestriction for disk chunks, overlay.admitLocked for overlay chunks), then select top-k over both. Phase 2: disk winners read C records, re-score with ScoreCoverage, resolve to paths; overlay winners go through overlay.resolve with the same score function. Apply post-filters (ChunkFilter, regex, proximity) to the top k, for which k is a candidate budget; WithVerify is ignored (R424, R710). Returns *SearchResults (R418-R425, R427, R706, R709)
- fileRestriction: Phase-1 view of WithOnly/WithExcept for disk chunks. Built from the F records of the restricted files: onlyChunks = chunks of files in only∖except, exceptChunks = chunks of excepted files. admitDisk(chunkID): with WithOnly, membership in onlyChunks decides; otherwise a chunk outside exceptChunks is admitted and one inside is admitted only if its C record shows a fileid outside the set (R707)
- searchConfig.fileAdmitted(fid): the single WithOnly/WithExcept test on one fileid, shared by scoreAndResolve, overlay resolution, and Phase-1 admission (R705, R706)
- SearchRegex(pattern, opts): extract trigram query from regex AST (rsc approach), evaluate boolean query against T records, apply ChunkFilter, score, then always verify — re-chunk file, run regex, discard non-matches. Apply regex/except-regex post-filters if present. Return SearchResults
- ScoreFile(query, fpath, fn, opts): extract trigrams, select via TrigramFilter, compute per-chunk scores for one file's chunks using given ScoreFunc. Apply ChunkFilter if present. Returns []ScoredChunk
- Reindex(path, strategy): re-chunk and re-index a file as a content diff that preserves chunkids for unchanged content (R673). reindexCore reads the old F record, deletes only the old F+N metadata (deleteFileMeta — not the chunks), adds the new chunks via addFileInTxn (the old chunks' H records are still present, so a chunk whose content hash is unchanged dedup-hits and keeps its chunkid while new content allocates), then drops the old fileid's occurrences (dropFileChunkOccurrences) so content that survived lives on under the new fileid and content gone from the file orphan-cascades. Returns (fileid, error)
- ReindexWithCallback(path, strategy, fn ReindexCallback, opts): same as Reindex but collects orphaned chunkids (content removed from the file — its last reference) and new chunkids, calls fn(txn, orphanedChunkIDs, newChunkIDs) inside the write transaction before commit. If fn returns error, entire txn aborts. If fn is nil, identical to Reindex
- ReindexWithContent(path, strategy): like Reindex but also returns the file content. Returns (fileid, []byte, error)
- PrepareFile(fpath, strategy, opts): compute phase — resolve chunker, read the file, chunk it, and per chunk compute hash/trigrams/tokens; return an opaque *PreparedFile carrying modTime/contentHash/fileLength. Opens no bbolt txn; safe from any goroutine while chunking config is not mutated (R676, R678). WithChunkCallback fires here (R683). Internally SplitFile→PrepareChunk per chunk→AssembleFile (R699)
- PrepareContent(fpath, strategy, content, opts): like PrepareFile but chunks caller-supplied bytes instead of reading disk (R677). Internally SplitContent→PrepareChunk per chunk→AssembleFile (R699)
- SplitFile(fpath, strategy): split step — resolve chunker, read the file, chunk it, and per chunk compute Hash=SHA-256(Content); return []SplitChunk plus FileMeta{modTime, contentHash, fileLength}. Extracts no trigrams/tokens. Opens no bbolt txn (R690, R693)
- SplitContent(fpath, strategy, content): like SplitFile but chunks caller-supplied bytes; opens no bbolt txn (R691, R693)
- SplitAppend(path, lastLocator, content, strategy, opts): split step for append — dispatch AppendAwareChunker.AppendChunks (or plain Chunks) against lastLocator, compute Hash=SHA-256(Content) per chunk, capture replacedLast; ErrAppendBoundary guard on zero chunks from non-empty content for a non-append-aware chunker. WithBaseLine offsets line-based ranges via adjustRange (default non-append-aware path only) and WithAppendChunkCallback fires during the split, as PrepareAppend does; the variadic is source-compatible. Returns ([]SplitChunk, replacedLast). Opens no bbolt txn, reads no committed state (R692, R693, R700)
- PrepareChunk(content): compute one chunk's content-pure grams (trigram counts + tokens) — no hash, no Range/Locator/Attrs; return opaque *PreparedChunk. Pure function of content and trigram config, cacheable/reusable by content hash. Opens no bbolt txn (R694)
- AssembleFile(fpath, strategy, entries, meta): assemble step — pair the ordered PreparedEntry list (positions/Attrs from each entry.Chunk, grams from entry.Grams, hash from entry.Hash) with FileMeta into the existing opaque *PreparedFile that StorePrepared/ReindexPrepared accept. Opens no bbolt txn; store side unchanged (R695, R696, R698)
- AssembleAppend(path, strategy, entries, replacedLast, lastLocator): assemble step for append — pair the ordered PreparedEntry list into the existing *PreparedAppend that AppendPrepared accepts, recording replacedLast and lastLocator for the tail check; positions/Attrs from each entry.Chunk. Opens no bbolt txn (R695, R697, R698)
- StorePrepared(p, opts): store phase for a fresh add — one Update txn: reject an already-consumed handle (R679), ErrAlreadyIndexed guard, allocate fileid, N records, addFileInTxn (H/C/T/F, counters), WithIndexedChunkCallback on new chunks; release the handle's content on success. Returns (fileid, error) (R680, R683)
- ReindexPrepared(p, opts): store phase for a content-diff reindex — one Update txn: look up the old F record, deleteFileMeta, add the prepared chunks under a fresh fileid (unchanged content keeps its chunkid), then dropFileChunkOccurrences. The removal set is derived in-txn from the committed F record, not supplied by the caller. ReindexCallback fires here. Returns (fileid, error) (R681, R682, R683)
- PrepareAppend(path, lastLocator, content, strategy, opts): compute phase for append — resolve chunker, dispatch AppendAwareChunker.AppendChunks (or plain Chunks), compute per-chunk hash/trigrams/tokens, capture replacedLast; ErrAppendBoundary guard. Returns an opaque *PreparedAppend carrying replacedLast and the assumed lastLocator. Opens no bbolt txn; the caller supplies path and lastLocator so compute reads no committed state (R685, R686). WithAppendChunkCallback fires here (R683). Internally SplitAppend→PrepareChunk per chunk→AssembleAppend (R699)
- AppendPrepared(fileid, p, opts): store phase for append — one Update txn: re-read the F record; when p.replacedLast, verify the committed last locator equals p's assumed locator, else ErrAppendTailMoved; then drop-and-replace + dedup + T + counters + F update. Returns error (R790, R688)
- Fused wrappers: AddFile, AddFileWithContent, the Reindex family, and AppendChunks are now compute-then-store compositions (PrepareFile+StorePrepared, PrepareFile+ReindexPrepared, and — reading the current tail from the F record — PrepareAppend+AppendPrepared); observable behavior is unchanged for existing callers (R684, R689)
- FileInfoByID(fileid): read F record for fileid, return FRecord. Wraps in a View txn
- FileSummaries(): one View over the F prefix; per record unmarshalFSummary decodes the header and the chunk count only, giving FileSummary{FileID, ModTime, FileLength, Strategy, ChunkCount} (R749, R750)
- ReadCRecord(tx *bbolt.Tx, chunkID): public power-user accessor — fetch C record by chunkID inside caller's bbolt txn, attach db/bucket to result for Bucket()/Tx()/DB()/FileRecord navigation (R664)
- ChunkContentLens(fileid): read F record chunk list, read each C record's ContentLen, return []int in chunk-list order. Single View txn. Overlay-aware (R500, R501)
- CheckFile(path): stat + hash to determine fresh/stale/missing using F record metadata
- StaleFiles(): scan F records, classify each, return []FileStatus
- RefreshStale(strategy, idxOpts): reindex all stale files, pass idxOpts through to reindex. Return ([]FileStatus, error)
- AddStrategy(name, cmd): add chunking strategy to I records
- AddChunker(name, c): register a chunker (Chunker, FileChunker, or both) as a strategy; validates at least one interface is satisfied. In-memory only, I record stores name with empty value. R293
- AddStrategyFunc(name, fn): convenience — wraps fn in FuncChunker, calls AddChunker. R294
- indexChunk(c): build a collectedChunk — the dedup hash is SHA-256 over the chunk's Content (R656, R657), the trigram/token index is built from that same Content (full-text, nothing stripped), and the chunk's native Attrs are stored. Shared by collectChunks, AppendChunks, the Prepare* compute entries, and the overlay's collectChunksFromContent.
- chunkAttrs(chunks, lo, hi): read the stored Attrs for chunks[lo..hi] from their C records in one View txn, keyed by chunkid — retrieval surfaces these stored native Attrs (R655)
- Attrs on retrieval (cross-cutting): retrieval re-reads Content from the file (original bytes) but reads each chunk's Attrs from the stored C record on every path — GetChunks (streaming + RandomAccessChunker fast path) and the tmp:// branch getChunksTmp (overlay.chunkAttrs) — so native chunker Attrs are surfaced consistently rather than dropped on the streaming/tmp paths (R655)
- AppendChunks(fileid, content, strategy, opts): chunk content using strategy, for each new chunk: fire ChunkCallback if WithAppendChunkCallback present (R482), hash, check H for dedup, create/update C records. Batch T updates. Update F record: append chunk entries, update metadata (no token bag since format "5", R769). Single bbolt write transaction. WithBaseLine adjusts line-based ranges after chunking. AppendAwareChunker dispatch: if the strategy's chunker implements AppendAwareChunker, read the F record's last entry's locator, call chunker.AppendChunks(path, lastLocator, newBytes, yield). When replacedLast=true, drop the F record's last chunk entry and run drop-occurrence cleanup on the dropped chunkid (decrement the chunkid's fileid count in its C record; cascade orphan cleanup via shared helper if that was the last reference). Chunkers that don't implement the interface get the default chunk-newBytes-and-append behavior. The dedup hash is SHA-256 over the chunk's Content (R656); a recomputed tail whose content changed hashes differently, gets a fresh chunkid, and fires WithIndexedChunkCallback on the new-chunk path.
- C record fileid refcounts: fileids list is stored as [fileid, count] pairs. add-occurrence increments the count for the fileid (insert with count=1 if absent). drop-occurrence decrements (count=0 removes the fileid entry; empty fileids list cascades orphan cleanup).
- F record chunk-list entries: shape is [chunkid, location, locator] — both location and locator are length-prefixed byte strings (either may be empty). Locator is the chunker-defined per-occurrence opaque bytes used by RandomAccessChunker and AppendAwareChunker.
- dropChunkOccurrence(chunkID, fileid): shared internal helper used by both RemoveFile's per-chunk cleanup and AppendChunks' drop-and-replace path. Reads the C record, decrements the fileid's count, removes the fileid entry on count=0; when fileids list is empty, deletes C and H, subtracts the chunk's tokenTotal from totalTokens and writes its D record; no posting is queued (R774).
- dropFileChunkOccurrences(frec, fileid, rcb): drop one file's occurrences from each of its chunks (seen-deduped over the F record's chunk list, removeFileID per chunk), orphan-cascade chunks that lose their last reference, decrement the totalChunks/totalTokens corpus counters, and return the orphaned chunkids. Does not touch F/N records. Shared by removeFileInTxn (whole-file removal) and reindexCore (dropping the old fileid's occurrences after the new chunks were re-added). R254, R673
- postingEdits: one write operation's T record additions, keyed by trigram, each holding the postings (chunkid, count) to append. addChunk queues a new chunk's postings; applyPostings rewrites each affected record once — dropping its dead postings (dead set, including this operation's orphans), keeping the survivors' order, appending the new postings after them, deleting a record left with no live posting (R778). Created by each write operation that adds chunks (AddFile/StorePrepared, reindexPrepared, appendPrepared), threaded through addFileInTxn, and applied before RemoveCallback/ReindexCallback fires (R784, R785).
- deadSet: the D records, loaded into a set where T records are read or rewritten (small; cleared by Purge). Every posting reader skips its ids (R775).
- Purge(): take the dead set as it stands; scan T records, rewriting each holding one of its ids without it (deleting empty ones), in batched write transactions; then delete those D records. Empty dead set: write nothing. Returns PurgeStats{Lists, Postings, Dead} (R779).
- ScoreFile(query, path, fn, opts): the selected trigrams' postings restricted to the file's chunkids give each chunk's counts (R777).
- T and C codecs: TRecord{Trigram, Postings} marshals delta<<1|hasCount uvarints with the count only when not 1 (R770, R780); CRecord carries DistinctTokens and TokenTotal and no lists (R771, R772); Create writes format "6", Open refuses others (R781, R782). No W record is written or read (R773).
- deleteFileMeta(fileid, fpath): delete a file's F record and N key chain only, leaving its chunks alone. Shared by removeFileInTxn (final step) and reindexCore (frees the path before addFileInTxn re-adds under a fresh fileid). R254, R673
- RemoveStrategy(name): remove chunking strategy from I records
- GetChunks(fpath, targetRange, before, after): look up file's F record for chunk list, find target by exact range label match (location field), compute neighbor window. Fast path: if RandomAccessChunker, build transient customData, for each i in window read C record by fileChunks[i].ChunkID for Attrs, pre-fill Chunk (Range, Attrs), call GetChunk. Streaming fallback: if FileChunker, call FileChunker.FileChunks(path, zero, yield); if Chunker, os.ReadFile + Chunker.Chunks; a windowMatcher keeps the yielded chunks whose Range is in the window and stops once all are found. Return []ChunkResult in positional order (R701)
- SearchMulti(query, strategies map[string]ScoreFunc, k, opts): single View txn — collect candidates once (trigram intersection, T/C record reads, chunk filters). Score with each ScoreFunc, keep top-k per strategy, apply post-filters per result set. Returns []MultiSearchResult
- BM25Func(queryTrigrams): read T records for per-trigram DF, read I record counters (totalTokens, totalChunks), compute IDF map and avgdl, return ScoreBM25 closure. Convenience for callers
- I record counter maintenance: AddFile/RemoveFile/AppendChunks atomically update totalTokens and totalChunks counters in the same write transaction
- AddTmpFile(path, strategy, content, idxOpts): delegate to overlay.addFile with ChunkCallback, return (fileid, error)
- AppendTmpFile(path, strategy, content, opts): delegate to overlay.appendFile with ChunkCallback from WithAppendChunkCallback, return (fileid, error). Shell >> semantics: create if absent, append if exists
- UpdateTmpFile(path, strategy, content, idxOpts): delegate to overlay.updateFile with ChunkCallback, return error
- RemoveTmpFile(path): delegate to overlay.removeFile, return error
- TmpFileIDs(): delegate to overlay.tmpFileIDs, return map[uint64]struct{}
- Search/SearchRegex/SearchMulti/ScoreFile: collect candidates from both the index and overlay, merge, apply filters and scoring uniformly
- GetChunks: detect tmp:// paths and route to overlay's stored content instead of disk; getChunksTmp matches by range through the same windowMatcher (R701)
- windowMatcher: pairs an F-record window [lo, hi] with re-chunked output by range label, never by position — yield records the content of each wanted range and reports done when none remain; results builds the window in F-record order, a range never yielded becoming a Missing result (F-record Range and Index, stored Attrs, empty Content). A chunker rule change after indexing then yields honest misses instead of a neighbor's content (R701, R702)
- BM25Func: sum index and overlay counters for true corpus size
- RecordCounts(): open read-only txn, iterate all keys in subdatabase, accumulate count/key bytes/value bytes per prefix. Return map[byte]RecordStats
- FileIDPaths(): return cached fileid→path map. Lazy load on first call (F record scan with UnmarshalFHeader). AddFile/RemoveFile/Reindex update cache incrementally
- chunkerVersion(strategy): the current version of the strategy's resolved chunker — VersionedChunker.ChunkerVersion() when implemented, else 0 (R715)
- chunkerStale(frec): frec.ChunkerVersion != chunkerVersion(frec.Strategy) — the one chunker-version predicate, used by classifyFile and the append store (R719, R727)
- classifyFile(frec): DB method. missing if the file is gone; stale if chunkerStale; fresh on matching mod time; else hash the content — fresh on match, stale otherwise (R64, R719)
- addFileInTxn stamps FRecord.ChunkerVersion = chunkerVersion(strategy), so add, reindex and both prepared stores record it; appendPrepared and SetFileLength rewrite the F record and carry it unchanged (R716, R760)
- appendPrepared: every append opens the txn — after re-reading the F record, refuse with ErrChunkerVersionStale when chunkerStale (R727); an append with no chunks and no replace stores no chunks but still records modTime/contentHash/fileLength (R728)
- StaleFiles: uses UnmarshalFHeader (not UnmarshalFValue) — skips Chunks and Tokens
- NewSearchCache(): set frecordCache, return cleanup func that nils it. readFRecord checks cache before the index
- Copy(): return shallow copy sharing bolt, dbName, settings, trigrams, overlay, chunkers. Caches (pathCache, pathToID, frecordCache) set to nil. overlayOnce not copied — overlay pointer shared directly
- InvalidateCaches(): nil pathCache, pathToID, frecordCache. Does not reset overlayOnce
- WithChunkCallback(fn): return IndexOption that sets ChunkCallback in indexConfig (R470)
- WithAppendChunkCallback(fn): return AppendOption that sets ChunkCallback in appendConfig (R471)
